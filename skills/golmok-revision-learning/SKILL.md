# 퇴고 학습 (golmok-revision-learning)

버전: 2026.11.11-1 · 층: 운영·설계

저자가 초안을 고친 자리가 김현성체의 가장 정확한 교재다. 이 스킬은 Claude가 쓴 초안과 저자가 실제로 올린 최종본을 견줘, 저자의 손이 지나간 곳만 골라 규칙 후보로 만든다. 문체 규칙은 golmok-writer 한 곳에만 둔다. 이 스킬은 규칙을 갖지 않고 규칙을 고치는 절차만 갖는다.

## 바탕 원칙

- **고친 곳만 근거다.** 최종본도 AI와 함께 쓴 글이다. 저자가 손대지 않은 문장은 승인한 것이 아니라 지나간 것일 수 있으니 문체의 근거로 삼지 않는다(golmok-writer 0장의 기준선과 같은 이유).
- **한 번은 관찰, 두 번은 규칙.** 한 편에서 한 번 고친 것은 그 글의 사정일 수 있다. 같은 방향으로 두 편에서 고쳤거나 저자가 말로 이유를 밝혔을 때만 규칙으로 올린다.
- **보탤 때 뺄 것도 본다.** 규칙이 늘기만 하면 스킬이 무거워지고 서로 부딪친다.

## 절차

### 1. 짝을 맞춘다

- 최종본에 맞는 초안을 찾는다. 같은 대화에 있으면 그것을 쓰고, 없으면 지난 대화를 제목과 핵심어로 찾는다.
- 초안이 여러 판이면 저자에게 마지막으로 넘긴 판을 쓴다.
- 초안을 찾지 못하면 추측으로 견주지 않고 저자에게 묻는다.
- 매체(칼럼·페북·연설 등)와 날짜, 제목을 적어 둔다.

### 2. 실제로 견준다

눈대중으로 하지 않는다. 두 글을 문장 단위로 나눠 차이를 뽑는다(스크립트를 쓸 수 있으면 쓴다). 차이마다 넷 중 하나로 표시한다: 지움, 보탬, 바꿈, 자리 옮김.

아울러 숫자로도 본다: 전체 글자 수, 평균 문장 길이, 문단 수, 대시·물음표·굵은 글씨 개수의 앞뒤. golmok-writer 12장 점검표의 항목을 최종본에 그대로 대 본다.

### 3. 고친 이유를 가린다

| 갈래 | 예 | 규칙이 될 수 있나 |
|---|---|---|
| 문체 | 어미, 문장 길이, 낱말 고르기, 표기, 말놀이 | 된다 |
| 구조 | 여는 법, 맺는 법, 문단 순서, 머리말과 PS | 된다 |
| 내용 | 사실 정정, 사례 추가, 주장 보탬 | 문체 규칙은 아니다. 사례 창고(11장)나 개념어 사전(10장) 갱신 후보 |
| 수위 | 세게 올림, 낮춤, 실명을 넣거나 뺌 | 매체와 상황을 함께 적어 관찰로 둔다 |
| 지면 사정 | 분량을 맞추려 자름, 편집자 요구 | 안 된다 |
| 알 수 없음 | 이유가 짐작되지 않는다 | 저자에게 묻는다. 묻는 것은 세 개까지 |

저자가 통째로 지운 문단은 따로 본다. 무엇을 썼는지보다 무엇을 못 견뎠는지가 더 분명한 신호다.

### 4. 지금 규칙과 맞대 본다

고친 곳마다 golmok-writer의 현재 SKILL.md를 읽고 셋 중 하나로 판정한다.

- **있는 규칙을 초안이 어겼다**: 새 규칙이 필요한 것이 아니다. 12장 점검표에 항목을 더하거나 문장을 더 분명히 고칠 것을 제안한다.
- **없는 규칙이다**: 관찰로 장부에 적는다. 두 번째 사례가 쌓였거나 저자가 이유를 밝혔으면 규칙 문안을 제안한다.
- **있는 규칙과 반대로 고쳤다**: 규칙이 틀렸거나, 매체가 다르거나, 이번만의 사정이다. 임의로 정하지 않고 저자에게 묻는다.

### 5. 제안한다

한 번에 규칙 제안은 세 개까지만 낸다. 제안마다 아래를 적는다.

- 초안 문장과 최종 문장을 나란히
- 넣을 자리(golmok-writer 몇 장)와 넣을 문안
- 함께 뺄 수 있거나 합칠 수 있는 기존 문장
- 본보기로 적을 글의 제목과 날짜

### 6. 승인 뒤에 반영한다

저자가 승인한 것만 반영한다.

1. golmok-writer의 현재 SKILL.md 전체를 읽고, 바뀐 곳이 반영된 전체본을 스킬 개정으로 제안한다. 부분만 보내지 않는다.
2. 버전 줄을 올리고 '버전' 절에 무엇을 왜 고쳤는지 한 줄을 더한다.
3. GitHub 저장소 goodmorninghope-khs/kimhyunsung-che에 같은 내용을 싱크한다. 커밋은 저자의 승인 뒤에 한다.
4. 규칙이 되지 못한 관찰은 같은 저장소의 퇴고 장부(revision-log.md, 없으면 만든다)에 날짜·글 제목·매체·고친 방향 한 줄로 적는다. 다음에 같은 방향의 수정이 나오면 여기서 두 번째 사례를 찾는다.

## 보고 형식

- 견준 글: 제목, 매체, 날짜, 글자 수의 앞뒤
- 저자가 고친 곳 몇 군데, 갈래별 개수
- 가장 눈에 띄는 수정 세 개(초안 → 최종)
- 규칙 제안(세 개까지)과 관찰로만 남길 것
- 저자에게 묻는 것(세 개까지)

## 하지 않을 것

- 저자가 손대지 않은 문장을 문체 근거로 삼는 일
- 한 번의 수정으로 규칙을 만드는 일
- 승인 없이 golmok-writer를 고치거나 GitHub에 커밋하는 일
- 문체 규칙을 이 스킬 안에 따로 쌓는 일
- 최종본을 다시 다듬어 주는 일. 이미 나간 글이다

## 넘겨줄 때

- golmok-writer · 승인된 규칙 문안과 본보기 · 저자가 승인했을 때 전체 SKILL.md 개정으로 제안한다.
- golmok-factcheck · 저자가 바로잡은 사실과 수치 · 사례 창고의 같은 수치가 다른 글에도 쓰였을 때 다시 확인한다.
- skill-map · 바뀐 golmok-writer의 버전 · 규칙 개정으로 다른 스킬과의 경계가 달라졌을 때 점검을 제안한다.
